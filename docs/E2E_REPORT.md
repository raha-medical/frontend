# تقرير فحص E2E (2026-11-03)

التشغيل: `start-native.bat` (PostgreSQL 16 المحلي `alrahma_db` + `dotnet run` على 8088 + Next على 3000).
الفحص من المتصفح على `http://localhost:3000` بحسابات حقيقية (`DEV_ACCOUNTS.local.txt` في المجلد الرئيسي).

## السيناريو الذي نجح من البداية للنهاية
1. المدير: دخول وتغيير كلمة المرور ← عيادة + مختبر + أشعة + صيدلية ← موظفون لكل دور ← جدول الطبيب ونسبه ← الخدمات وقالب التحليل ← تسجيل حاسوب الاستقبال وشاشة الانتظار.
2. المريض (التطبيق): OTP `000000` ← إنشاء ملف ← حجز ← دفع إلكتروني تجريبي ← الحجز «مدفوع».
3. الاستقبال: فتح وردية ← تثبيت حضور المحجوز (مدفوع) ← مريض جديد حضور مباشر ← تحصيل نقدي وطباعة إيصال.
4. الطبيب: استدعاء ← دخل ← تشخيص + وصفة + طلب تحليل وأشعة ← حفظ وإنهاء واستدعاء التالي.
5. الاستقبال: تحصيل التحليل والأشعة (POS) ← المختبر: سحب العينة ← بدء ← نتيجة (منخفض) ← اعتماد ← الأشعة: تقرير ← الصيدلية: صرف الوصفة (ومنع الصرف المكرر).
6. الاستقبال: إغلاق أعمى للوردية ← المحاسب: «مطابق» واعتماد. اللوحة: 85,000 صافي / 3 دفعات، حصة الطبيب 35,000.
7. فتح كل صفحات الأدوار (إدارة 11، استقبال 8، طبيب 4، محاسب 11) بدون أي خطأ من الـ API.
