# ابدأ من هنا

## شاشة الانتظار والحضور من الهاتف

التصميم الجديد نصف QR للحضور ونصف للطابور. تطبيق المراجع يمسح رمز الشاشة بدلاً من عرض رمز خاص به، ويمكن فتحه من كاميرا الهاتف ثم تأكيد حضور الحجز. يلزم رابط واجهة متاح للهاتف (وليس localhost)، مع HTTPS للكاميرا المباشرة. انظر [التشغيل والتفاصيل](docs/waiting-screen-checkin.md).

## الوصفة الطبية النصية

الطبيب يكتب الوصفة كاملة في Text Area واحد (حتى 10,000 حرف)، وتظهر كما هي في الصيدلية وملف المريض والطباعة. الصيدلي يحدد علاجات الصرف من قائمته وكمياتها يدوياً دون تفسير آلي للنص. الوصفات القديمة مدعومة؛ لا تتغير عند حفظ التشخيص دون تعديل الوصفة. يلزم تطبيق `backend/database/migrations/031_prescription_text.sql` قبل تشغيل API الجديد. لا يمكن تعديل وصفة سُعّرت أو صُرفت. تفاصيل العقد في `../backend/docs/prescription-text.md`.

## تحديث الصيدلية

«قائمة العمل» تفصل إحالات الأطباء عن المراجعين المباشرين. «العلاجات والأسعار» تتيح الإضافة والتعديل بصلاحية `pharmacy.dispense` في الصيدلية والفرع الحالي فقط. الكمية للمريض وقت الصرف، وليست مخزونًا. فتح الوصفة من اسم المراجع وزر «صرف»، دون QR أو كتابة كود. يمكن إعادة فتح طلب المراجع المباشر ومتابعة التحصيل والتسليم. التفاصيل في `../backend/docs/pharmacy-workflow.md`.

## تحديث واجهة المختبر

من قسم المختبر: «التحاليل والأسعار» لعرض الكتالوج وإضافة التحاليل وتعديل أسعارها بصلاحية `lab.write` في الفرع الحالي فقط. «مراجع مباشر» يسجل الاسم والهاتف ويختار تحاليل دون إحالة، ثم يتابع التحصيل المعتاد. فلتر «إحالات الأطباء / مراجعة مباشرة» يعمل في قائمة العمل والمنتظرة والمكتملة. أزيل ماسح QR من إحالات المختبر، وبقي تأكيد الحضور اليدوي وباركود العينة. تفاصيل المسارات والحدود في `../backend/docs/lab-workflow.md`.

1. اسحب المستودعات الثلاثة (backend, frontend, dock) على الفرع `staging` في مجلد واحد.
2. شغّل النظام كما في [`backend/README.md`](../backend/README.md) (قسم «التشغيل لأول مرة»)، والحسابات في [`dock/docs/handoff/accounts.md`](../dock/docs/handoff/accounts.md).
3. اقرأ [`dock/docs/handoff/ui-requirements-handoff.md`](../dock/docs/handoff/ui-requirements-handoff.md) واتبع منهجية وكيل الجودة (القسم الأخير فيه، والوكيل في `.claude/agents/ui-qa.md`).
4. اعمل على الفرع `ui/redesign` من `staging`، وادمج عبر Pull Request.

# واجهة مجمع الرحمة الطبي (Frontend)

Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS 3 + Dexie (IndexedDB) + PWA.
المرجع: `../backend/docs/api_contracts.md` (العقد هو المرجع عند أي اختلاف مع swagger) والتصميم في `هوية بصرية لمجمع الرحمة/design_handoff_rahma`.

## التشغيل
1. شغّل الباك اند: `docker compose up --build` داخل `alrahma-backend-final` (الـ API على `http://localhost:8088`).
2. هنا: `npm install` ثم `npm run dev` ثم افتح `http://localhost:3000/staff/login`.
3. حساب البداية: `admin` / `Admin-Change-Me-2026` (يُطلب تغييرها عند أول دخول).
4. التحقق من الأنواع والبناء: `npm run typecheck` و`npm run build`.

الإعدادات في `.env.local` (نسخة من `.env.example`):
`NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_AGENT_MODE` (`simulate` | `agent`), `NEXT_PUBLIC_AGENT_URL`, `NEXT_PUBLIC_DEVICE_CODE`.
> `NEXT_PUBLIC_DEVICE_CODE` = `device_code` لجهاز استقبال مسجّل في الباك اند. بدونه لا تعمل المزامنة وكتل الإيصالات.

> **بدون Docker:** شغّل `start-native.bat` من المجلد الرئيسي (يستخدم PostgreSQL 16 و.NET 8 المثبتين على ويندوز، ويطلب كلمة مرور مستخدم `postgres`).
> **المنافذ:** الـ API على **8088** (لأن 8080 محجوز لـ WildFly على هذا الجهاز)، وقاعدة Docker على 55432 (لأن 5432 محجوز لـ PostgreSQL المحلي). افتح الواجهة دائماً على `http://localhost:3000` وليس `127.0.0.1` أو منفذ آخر، وإلا يرفض الـ CORS الدخول.

## حالة الشاشات (مطابقة لملفات التصميم)
جلسة الموظف محفوظة في `sessionStorage` لكل تبويب: تبقى بعد تحديث الصفحة، ويؤثر تسجيل الخروج على التبويب نفسه فقط. افتح تبويباً جديداً وسجّل الدخول بالحساب المطلوب. قد ينسخ المتصفح جلسة التبويب عند تكراره (Duplicate)، ثم تصبح النسختان مستقلتين محلياً؛ لدخول مستقل افتح تبويباً جديداً بدلاً من تكراره. جلسة المريض والتفضيلات تبقى في `localStorage`.

بعد هذا التحديث يلزم تسجيل دخول الموظفين مجدداً؛ لا تُستورد الجلسة القديمة من `localStorage`. بيانات الأوفلاين والصندوق الصادر معزولة حسب الموظف والفرع. قاعدة IndexedDB القديمة `rahma` محفوظة دون حذف، وعملياتها المعلقة لا تُرسل تلقائياً لأنها لا تحتوي هوية صاحبها؛ يجب مراجعتها قبل ترحيلها يدوياً.

| القسم | المسار | الشاشات |
|---|---|---|
| الاستقبال | `/staff/reception/*` | الطابور، الحضور، التحصيل، طلب مباشر، الاسترجاع، فك الحظر، الوردية، المزامنة |
| الإدارة | `/staff/admin/*` | المستخدمون، الفروع، الأقسام، الأطباء، الخدمات وقالب التحليل، الدمج والتدقيق، الأجهزة، القوائم، الإعدادات، النسخ الاحتياطي، الرسائل التجريبية |
| الطبيب | `/staff/doctor/*` | طابوري، المعاينة، سجل المريض، الإشعارات |
| المختبر والأشعة | `/staff/diagnostics/lab` و`/radiology` | قوائم العمل، العينة، النتائج والاعتماد والتعديل، الجدولة والتقارير |
| الصيدلية | `/staff/pharmacy/*` | صرف وصفة، المصروف اليوم |
| المحاسب | `/staff/accountant/*` | اللوحة، المطابقة، اعتماد الاسترجاع، الآجل، الإيراد، أرباح الأطباء، الفواتير، المصاريف، التسويات، الغياب، التدقيق |

## تسلسل أول تشغيل (E2E)
1. ادخل بـ `admin` وغيّر كلمة المرور.
2. الإدارة ← الأقسام: أضف عيادة ومختبراً. ← المستخدمون: أضف طبيباً (مع ملف الطبيب) وموظف استقبال وفني مختبر وصيدلياً ومحاسباً.
3. الإدارة ← الأطباء: الجدول الأسبوعي والنسب. ← الخدمات: كشفية جديد ومراجعة، وتحليل مع قالبه.
4. الإدارة ← الأجهزة: سجّل «حاسوب استقبال» وضع رمزه في `NEXT_PUBLIC_DEVICE_CODE`، وسجّل «شاشة انتظار» وافتح رابطها.
5. المريض: `/patient` برقم هاتف ورمز `000000` ← حجز ← دفع تجريبي.
6. الاستقبال: فتح وردية ← حضور ← تحصيل ← الطبيب: دخل ← معاينة + طلب تحليل ← الاستقبال: تحصيل التحليل ← المختبر: عينة ونتيجة واعتماد ← الصيدلية: صرف الوصفة ← الاستقبال: إغلاق الوردية ← المحاسب: مطابقة الوردية.

## قواعد ملزمة
- لا استدعاء `fetch` للـ API خارج `lib/api`. كل POST يحمل `Idempotency-Key` تلقائياً، وإعادة المحاولة تمرّر نفس المفتاح عبر الخيار `idempotencyKey`.
- الأخطاء تُقرأ من `code` (`lib/api/errors.ts`) وليس من النص.
- لا تُرسل الأسعار ولا هوية المستخدم. لا تحسب نسب الأطباء في الواجهة؛ السيرفر يحسبها (العقد 0.4).
- المبالغ أعداد صحيحة بالدينار (`fmtIqd`)، والتواريخ UTC تُعرض بتوقيت بغداد عبر `lib/format.ts` فقط: أشهر عراقية (كانون الثاني، شباط…) ووقت 12 ساعة بـ ص/م.
- خط واحد للنظام كله: Readex Pro. الأرقام لاتينية جدولية بالصنف `num`. العناوين الفرعية الصغيرة بالصنف `sub` (12–13px، وزن 600).
- الألوان من توكنز `app/globals.css` فقط (فاتح/داكن)، لا ألوان ثابتة داخل المكونات، ولا أصفر/برتقالي. المكونات المشتركة (DataGrid، ISelect، Badge…) ودليل نظام التصميم في `components/ui/README.md`.
- لا بيانات وهمية داخل الكود: الربط على الباك اند الحقيقي. لا كلمات مرور في Git.
